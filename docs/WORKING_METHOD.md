# Working Method

## 核心规则：用目标状态指导生成与实现

FocusWave 的设计协作采用肯定式规格。每条指令直接描述希望出现的结构、行为、气质、数据关系和验证标准。

这条规则同时适用于：

- 设计讨论
- 图像生成提示词
- UI / UX 规范
- 前端实现
- Codex 任务说明
- 研究原型迭代

## 根因修复流程

### 1. 定义目标状态

先写清最终结果应该是什么。

示例：

- “首屏由大面积暖白留白、左侧状态文本、右侧毫米波细线流场和底部轻量指标组成。”
- “主视觉保持数据原生、连续、非对称、低对比，并随着状态缓慢演化。”
- “人文层使用自然书写气质的屏显字体，数据层使用现代 UI 字体。”

### 2. 定位上层机制

分析当前结果偏离目标的原因，优先寻找能够同时解释多个表面问题的上层规则，例如：

- 视觉中心定义
- 信息层级
- 数据映射逻辑
- 意象进入界面的方式
- 色彩角色
- 字体角色
- 生成提示词结构

### 3. 直接改写主规则

找到根因后，直接重写主规范，并同步更新依赖该规则的文档。主规则承担长期约束，局部实现从主规则自然派生。

### 4. 用产物验证

根据问题类型选择验证方法：

- 视觉问题 → 同版式效果图对比
- 交互问题 → 可操作原型
- 数据艺术问题 → 参数映射演示
- 调节假设 → A/B 或被试内实验
- 字体问题 → 同一母版、同字号层级的字体样张

## 肯定式规格模板

每条设计规则优先回答五个问题：

1. 页面由什么构成？
2. 哪个元素承担视觉中心？
3. 每个元素承担什么语义？
4. 状态变化通过哪些参数表达？
5. 用什么结果判断设计成立？

## 生成式模型协作原则

提示词围绕目标视觉语言组织：

- 指定空间结构
- 指定主视觉来源
- 指定线条、材质、色域与动态
- 指定数据映射关系
- 指定字体层级
- 指定留白比例与信息密度
- 指定验证用的状态变量

这样生成模型获得完整目标空间，并围绕结构、语义、数据关系和视觉行为进行生成。
